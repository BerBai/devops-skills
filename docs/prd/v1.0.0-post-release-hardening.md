# v1.0.0 发布后硬化：lint 基线、4 个红测试、ADR 恢复、Vale 全树

## 背景

`v1.0.0` 的版本元数据已经统一：marketplace、`pyproject.toml`、8 个
`plugin.json`、ssh-core 的 `lib/version.py` 和 `uv.lock` 均为 `1.0.0`；
`uv lock --check` 通过；`v1.0.0` tag 从本发布 commit 切出。

发布门禁仍有三类未闭合项：

1. `ruff check .` 仍报 **444** 条；`lint` job 不可能绿。
2. `pytest tests/ -q` 仍有 **4 failed / 2005 passed / 151 skipped**；失败是
   平台/DNS 假设，不是功能缺失，但也不能算绿。
3. `pyproject.toml`、`ci.yml`、`tools/check_python_floor.py` 引用 **ADR-006**，
   但仓库没有 ADR-006；ADR-001/002/003 也只有代码注释引用、无文件。
4. Vale 当前只在 13 个可解析文档上为 0；8 个 `SKILL.md` 因 YAML frontmatter
   无法解析，27 个 references 有 181 条拼写/代码格式告警。

本任务只做发布硬化，不新增功能、不重写文档、不重做 8 个插件。

## 目标

- 让 `v1.0.0` 的 lint / test 门禁有明确、可复跑的绿色口径，或显式、可审计的
  基线；不允许“命令红着但文档写绿”。
- 让 ADR 引用链完整：ADR-001/002/003/006 要么有带来源的正文，要么从引用处
  删除。
- 让 Vale 的“0”有明确范围：全树 0，或配置中逐项列出的排除范围。

## 非目标

- 不修改插件运行时行为（除为通过确定性测试所需的最小修复）。
- 不把 444 条 ruff 一次性清零；允许分阶段基线，但必须可度量、只降不升。
- 不补齐 181 条 references 的全部文风问题；Vale 只处理可机器判定的类别。
- 发布动作（commit / tag / push）按 R5 单独执行；实现阶段不提前打 tag。

- `docs` job 的 Python 门禁保持 stdlib-only；Vale/markdownlint 的网络依赖需显式

  Linux 回归；本轮四项以本地/CI 为主。
- 不在未提交的工作树上创建 tag；不 push，除非用户明确要求。

## 风险与开放问题

1. **ssh-core 版本下调**：`1.5.0 → 1.0.0` 对比较版本的外部消费者是降级；
   已在 `version.py` 和 ADR-004 写“distribution version vs feature history”。
   若未来要求单调递增，需要重新设计版本方案。
2. **ruff 棘轮可能掩盖债务**：必须记录基线、负责人和复审日期，否则 444 会
   长期合法化。
3. **ADR-006 无历史正文**：按证据重建必须显著标注 reconstructed；不要把重建
   文本伪装成历史原文。
4. **Vale 的全树 0 成本**：8 个 SKILL frontmatter 加引号会改 8 个文件；词表和
   181 条修复需要单独 review，不宜混进版本发布 commit。
